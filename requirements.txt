NU-Information Exchange System (FAST-NUCES Multi-Campus Network)
1. Objective
The primary objective of this project is to design and implement a system that models the
information exchange between multiple FAST-NUCES campuses. This project is divided into
two distinct parts:
● Application Development: Implement a multi-client communication system using C/C++
socket programming to handle inter-campus communication.
● Network Architecture: Design the underlying Wide Area Network (WAN) topology in
Cisco Packet Tracer that connects the various FAST-NUCES campuses across Pakistan.
2. Learning Outcomes
Upon successful completion of this project, you will be able to:
● Implement a client-server architecture using C/C++ sockets.
● Utilize both TCP (for reliable, connection-oriented communication) and UDP (for
connectionless, low-overhead broadcasts).
● Analyze the trade-offs between TCP and UDP for different application needs.
● Manage multiple concurrent client connections on a server.
● Design a multi-site WAN topology in Cisco Packet Tracer.
● Configure IP addressing, subnets, and basic routing (static or dynamic) to enable end-to-
end connectivity between different networks.
4. Application Development (Lab - 20 Marks)
This part involves creating software for the NU-Information Exchange System using C/C++
socket programming. The system will be console-based (GUI can also be implemented).
4.1. Application Architecture
The system will follow a client-server model designed to represent the multi-campus structure of
FAST-NUCES.
● Central Server (e.g., Islamabad Campus): A single server application that acts as the
central hub. It manages connections with all other &quot;Campus Clients.&quot;
● Campus Clients (e.g., Lahore, Karachi, Peshawar, CFD, Multan): Each of these is a
separate client application. From the server&#39;s perspective, they are &quot;clients.&quot; From a user&#39;s
perspective, they are the local &quot;server&quot; for that campus.
● Department Users: We will simulate users from departments (Admissions, Academics, IT,
Sports) by having them interact with their local Campus Client via its console.

3. Protocol Design
3.1 When to Use TCP vs. UDP
You must implement a hybrid TCP/UDP approach. The rule is simple: if the message matters and must
arrive reliably, use TCP. If it is a periodic update or broadcast, use UDP.

TCP • Campus authentication (login)
• Campus-to-campus direct messages
• Receiving admin commands

4. Implementation Guide
4.1 Central Server Module
The Central Server is the most complex component. Plan it carefully before you start coding.

What your server must do
1. Open one TCP port (e.g., 9000) — listens for campus client connections
2. Open one UDP port (e.g., 9001) — listens for heartbeats
3. For each new TCP connection, spawn a thread (std::thread) to handle that client
4. Validate the AUTH message against hard-coded credentials
5. Parse incoming MSG packets and forward them to the correct destination socket
6. Display all UDP heartbeats on the admin console
7. Accept broadcast text from the admin console and send it via UDP to all clients

Concurrency Tip
Use std::thread to handle each Campus Client in its own thread. You will also need a separate thread
to listen for UDP datagrams. Protect shared data structures (e.g., the list of connected clients) with a
std::mutex.
// Skeleton — accepting connections and spawning threads
while (true) {
int clientSock = accept(tcpSock, ...);
std::thread t(handleClient, clientSock);
t.detach();
}

Message Routing Logic
When a MSG packet arrives from Campus A, your server must:
1. Parse the destination campus name from the packet
2. Look up that campus in your connected-clients map
3. Forward the raw packet to that client&#39;s socket

Heartbeat Thread
Run a loop in a separate thread that sends a UDP packet to the server every 10 seconds:
void heartbeatThread(int udpSock, ...) {
while (running) {
std::string pkt = &quot;HEARTBEAT|Lahore|&quot; + currentTime();
sendto(udpSock, pkt.c_str(), pkt.size(), 0, ...);
std::this_thread::sleep_for(std::chrono::seconds(10));
}
}

Compile with the POSIX thread library. Below are example commands for Linux/macOS and Windows
